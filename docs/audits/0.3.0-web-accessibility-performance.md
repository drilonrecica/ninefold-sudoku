# 0.3.0 web accessibility and performance audit

Audit date: 2026-07-25

This audit covers the current MVP routes and states. It is an engineering conformance review, not
a third-party WCAG certification.

## Environment

- Chrome for Testing 147.0.7727.15 on Linux/Wayland
- Playwright 1.61.1 and axe-core 4.10.2
- Orca 50.2 / AT-SPI 2.60.5 semantic-output review
- Node.js 24.14.1 and pnpm 11.12.0
- Local production build served over loopback; no browser extensions

## Accessibility results

Automated axe checks report no serious or critical violations on Home, How to Play, Privacy,
Accessibility, Settings, Lobby, Co-op gameplay, replay, and Solo flows. Core interactive states are
also checked with the full axe rule set.

The keyboard and accessibility-tree walkthrough covered:

- skip-link order and visible focus;
- create, join, ready check, match start, board entry, notes, hints, completion, replay, rematch,
  and Solo resume;
- board row/column, clue/editable state, value, notes, conflict, pending state, and participant
  attribution;
- connection, recovery, validation error, readiness, result, and replay status announcements;
- safe initial focus and focus restoration for destructive local-data confirmation;
- Escape, arrows, digits, Backspace/Delete, N/Space, and H shortcuts without focus traps.

The visual walkthrough covered 320, 375, 430, 768, 1024, 1280, and 1440 CSS-pixel widths; 200%
browser zoom; light and dark color schemes; reduced motion; enhanced contrast; pseudo-localized
expansion; and touch/keyboard input. Board cells remain at least 24×24 CSS pixels and primary
controls/number-pad buttons at least 44×44 CSS pixels. Status does not rely on color alone.

Native screen readers can differ. The supported baseline is current Chromium with the Linux
AT-SPI/Orca combination above; VoiceOver and NVDA were not available in this environment and are
not claimed as tested.

## Public performance

Lighthouse 13.0.1 was run three times against the production build with simulated mobile
throttling. The median scores were:

| Category | Score |
| --- | ---: |
| Performance | 100 |
| Accessibility | 100 |
| SEO | 100 |

Median measurements were 1.2 s first contentful paint, 1.4 s largest contentful paint, 0 ms total
blocking time, and 0 cumulative layout shift. The first cold browser process reported performance
81 because of 1.5 s of unattributable process-startup work; both repeat page runs scored 100.

The committed budget check measures every statically imported JavaScript chunk once using gzip:

| Entry | Compressed JavaScript | Budget |
| --- | ---: | ---: |
| Home | 37.7 KiB | 100 KiB |
| Multiplayer gameplay | 49.8 KiB | 200 KiB |
| Solo gameplay | 74.8 KiB | 200 KiB |

Public pages use system fonts, contain no raster images, declare dimensions on the inline brand
mark, make no third-party requests, and render meaningful server HTML without client JavaScript.
Hashed build assets are ready for immutable caching; response cache policy is verified with the
production hardening work.

## Reproduction

```sh
make build
pnpm --filter @ninefold/web e2e
pnpm --filter @ninefold/web budget
pnpm --filter @ninefold/web preview --host 127.0.0.1 --port 4174
pnpm dlx lighthouse@13.0.1 http://127.0.0.1:4174/ \
  --only-categories=performance,accessibility,seo
```
