# Ninefold Sudoku 0.3.0 qualification

Qualification date: 2026-07-25

Release: `0.3.0` full MVP / portfolio beta

Base candidate: `3203145` (`feat(ops): add secure production operations`)

Final reference: annotated tag `v0.3.0` on the Phase 16 commit

This report records reproducible release evidence, not raw logs. No production deployment, DNS
change, secret creation, image publication, or remote mutation was performed.

## Scope freeze

Enabled current features are Co-op, online Solo, replay integrity, replay deletion, rematch,
English, pseudo-localization testing, accessibility support, private operations, and Coolify
packaging. Race, Duel, Daily Ninefold, offline Solo/PWA, Explain hints, full spectator UX,
additional locales, accounts, public matchmaking, and analytics remain absent.

The root and web package versions are `0.3.0`. Contract schema, replay proof, rule, migration, and
puzzle-tool versions are frozen at their committed values. Migration 16 is the current database
schema.

## Load and resilience

`TestQualificationLoad100Connections25Rooms` creates 25 Rooms and 100 isolated cookie sessions
against the real HTTP server and file-backed SQLite, upgrades 100 WebSockets concurrently, leaves
clients temporarily unread, checks bounded actor/outbound queues, disconnects all clients, and
repeats the 100-connection storm. It passes normally and under the race detector; the local run
completed in 0.20 seconds. Focused suites additionally cover simultaneous commands/completion,
SQLite write pressure, interrupted/idempotent maintenance, slow-reader disconnect, graceful
shutdown, snapshot restart, and recovery.

## Security and privacy

The following passed:

```sh
go run golang.org/x/vuln/cmd/govulncheck@v1.1.4 ./...
pnpm audit --audit-level high
trivy image --severity HIGH,CRITICAL ninefold-server
trivy image --severity HIGH,CRITICAL ninefold-web
```

`govulncheck` found no reachable vulnerabilities. pnpm reported no high or critical vulnerability
after pinning patched transitive `js-yaml` and `brace-expansion` releases. Both final runtime images
reported zero high/critical findings. The web runtime excludes package managers and build tools.

Tests verify strict Origin handling, secure HTTP-only cookies, body/header/WebSocket limits,
progressive Room-code blocking, rotating keyed IP digests, capability authorization, replay
deletion, security headers, trusted-proxy-only administration, confirmation/audit behavior, and
log/metric redaction. The built client has no third-party analytics or tracking requests.

## Containers and operations

Both images build from frozen inputs, run as non-root, carry immutable version labels, and pass with
read-only root filesystems. `/app/data` is the server's only required persistent writable path.
The locally qualified image IDs are `sha256:5913fe8a1a32…` for the server and
`sha256:bd195587790b…` for the web image; both report version `0.3.0`.
The local Caddy route passed HTTPS homepage/readiness, secure-cookie issuance, allowed and rejected
Origins, `101` WebSocket upgrade, private route handling, SQLite persistence across restart, and a
0.27-second graceful shutdown. Caddy configuration and Compose expansion validate successfully.

The Coolify runbook defines separate web/server applications, one SQLite volume, health checks,
private proxy identity, owner-supplied secrets, immutable tags, startup ordering, and
rollback-compatibility checks. No previous tagged image pair exists because `0.3.0` is the first
release; pair rollback can only be exercised after a subsequent release.

## Accepted non-blocking limitations

- This is the portfolio beta, not the Product §32 public-ready `1.0.0` release.
- Off-VPS backup/restore is intentionally deferred; private testing accepts data-loss risk.
- The deployment-specific same-region acknowledgement budget must be measured after owner-approved
  deployment.
- NVDA, VoiceOver, Firefox, and WebKit require later environment-specific review.
- GitHub Actions links are unavailable because the release commit and tag are not pushed by this
  task. The pinned workflow and all local equivalent checks pass; CI will run when the owner pushes.

There are no accepted critical/high security findings, invariant failures, accessibility blockers,
or unexplained browser-budget misses.
